## v0.0.27 · 模型站生态、双阶段人声修复与离线安装

> 本次更新把阶段四模型站生态、模型上传与试听、高音域翻唱、专用人声修复模型、FCPE 适配、离线 Wheelhouse 和安装器分卷约束统一归入 **v0.0.27**。重点是让模型站围绕 ModelScope 公开仓库完成分享与下载，让高音翻唱和模型输出拥有更完整的音频保护，同时让用户机安装尽量不依赖现场下载与编译。

> [!IMPORTANT]
> v0.0.27 使用分卷安装包。请同时下载 `XB-SVCB-Setup.exe` 和同版本的全部 `XB-SVCB-Setup-*.bin`，放在同一目录后再运行安装程序；每个分卷均小于 2 GiB，缺少任意分卷都无法完整释放内置资源。

### 🌐 模型站详情与后台传输

- 模型站新增完整模型详情：展示模型框架、版本、发布时间、标签、说明、依赖状态、下载统计、截图和试听素材；搜索支持关键词模糊匹配、框架筛选、分页加载和详情查看。
- 搜索结果支持按综合排序、下载量和更新时间排列；模型清单继续执行框架与文件角色校验，避免不符合 XB-SVCB 格式的仓库被误识别为可用模型。
- 上传模型时可以填写版本、说明和标签，并附带截图与试听音频；上传、下载和升级继续使用后台任务、进度轮询、断点续传和失败重试，不阻塞主界面。
- 下载完成后会写入模型来源仓库、来源版本和发布时间，并立即刷新模型列表；模型站令牌只用于上传到用户自己的 ModelScope 命名空间。
- 模型详情支持检查已安装模型的新版本并发起后台升级，升级完成后保留本地模型使用记录和来源信息。

### 🎧 模型试听与素材校验

- 试听音频大小限制为 **不超过 1 GiB**，选择、上传前和服务端都会检查真实文件内容。
- 扩展名伪装、无法解码、媒体类型不匹配或非音频文件会被拒绝；支持常见音频格式，最终以音频解码和媒体类型校验结果为准。
- 试听通过模型站远端素材地址播放，避免把大型音频完整编码进前端内存，也不会把本机临时文件当成公共试听地址。
- 模型截图和试听音频作为模型仓库素材统一管理，模型详情和搜索结果读取同一份远端资源信息。

### 🎙️ 双阶段专用人声修复

- 人声分离与去混响后的处理链调整为：`UVR 分离 → 去混响 → DeepFilterNet3 修复分离人声 → 高频/音域分析 → F0 提取 → 模型推理 → DeepFilterNet3 修复模型输出 → 可选 AI 歌声增强 → 混音`。
- 分离人声先使用安装包内置的专用 `DeepFilterNet3` 模型修复分离伪影；翻唱模型输出后再执行一次较轻的独立修复，然后进入可选美声和最终混音。
- 修复前分析频谱质心、6 kHz 以上高频占比、有效人声活动和音高分布；高频或高音素材会降低神经修复衰减，避免清辅音、气声和高音泛音被过度抹除。
- 神经修复后只在有效人声窗口受控恢复高频瞬态，不向静音段重新注入噪声；修复失败时保留可诊断日志，并继续使用可用的上一步音频完成后续流程。
- 单模型、自动多模型和手动多模型流程均增加“分离人声修复”和“输出人声修复”状态，前端进度步骤与后端任务日志保持一致。

### 🎼 高音域自适应与 FCPE

- 音域分析根据 F0 P95 和最高音计算推理上限，默认 F0 上限不低于 `1100 Hz`，极高音素材最高扩展到 `1800 Hz`；自适应上限会传入实际推理 worker，而不是只改变界面显示。
- 检测到高音或高频后，会降低 F0 中值滤波半径和清辅音保护阈值，减少高音被过度平滑、降八度或错误截断。
- So-VITS-SVC 检测到高音时优先使用随包 FCPE，缺失时回退 CREPE；DDSP-SVC 使用 FCPE；RVC 使用 CREPE，不会强行把不兼容的 FCPE 传给 RVC。
- 修复 So-VITS-SVC 选择 FCPE 时因缺少 `einops` / `local-attention` 导致推理中止的问题；FCPE 初始化仍发生异常时会自动回退 CREPE，并保留本次任务的自适应 F0 上限。
- FCPE 只负责音高 F0 识别，`DeepFilterNet3` 负责音频修复，两者职责不同；FCPE 权重随安装包分卷携带，并部署到 So-VITS-SVC 的 `pretrain/fcpe.pt`。
- 创建页单模型、多模型和 Audio Editor Lite 局部重推理均可手动选择 FCPE。So-VITS-SVC 和 DDSP-SVC 显示 FCPE，RVC 不显示，SeedVC 隐藏 F0 选择；切换到不兼容框架时，失效选择自动回退为 `rmvpe`。
- AMD DirectML 环境下，主翻唱模型继续使用显卡，RMVPE / FCPE 使用 CPU 稳定路径，避免不受支持算子导致任务失败。

### 📦 离线 Wheelhouse 与安装器分卷

- 发布构建会预先下载或构建 `uv` 和各 AI 环境需要的 Windows x64 whl，并按 Python 版本、CPU、AMD DirectML、NVIDIA cu121、NVIDIA cu128 和冲突组件拆分 Wheelhouse。
- 安装器根据用户机器的 Python 版本、GPU 栈和组件自动选择对应 Wheelhouse；用户机创建或修复环境时使用 `--no-index --no-build --find-links` 离线安装，不再现场下载 PyPI 包或编译源码包。
- 发布构建生成 `assets/wheels/wheelhouse.json`，记录平台、依赖分组和 Wheel 数量，并拒绝空分组；发布侧会处理镜像缺包、只有源码分发以及组件间 Torch 版本冲突。
- 针对 Python 3.9 的 So-VITS-SVC，Wheelhouse 显式携带 `importlib-resources>=3.2.0`，并对已验证的 `matplotlib==3.7.5` 使用无依赖安装，避免旧版缓存 Wheel 导致解析失败或把 NumPy 升到不兼容版本。
- 所有 So-VITS-SVC 的 CPU、AMD DirectML、NVIDIA cu121 和 cu128 Wheelhouse 均固定携带 `einops==0.8.2` 与 `local-attention==1.10.0`；环境搭建完成前会真实导入 FCPE 模块校验，旧安装可从开始菜单运行“搭建/修复运行环境”并只修复 `svc` 组件。
- `fcpe.pt`、DeepFilterNet3 和其他底模随安装分卷携带；关键资源缺失、体积异常或疑似 Git LFS 指针时构建直接失败。
- Inno Setup 的 `DiskSliceSize` 固定为 `1,900,000,000` 字节，构建完成后逐个检查安装产物；任何达到 `2 GiB` 的分卷都会阻止发布。
- 安装时必须把 `XB-SVCB-Setup.exe` 和全部 `XB-SVCB-Setup-*.bin` 放在同一目录；分卷发布、离线模型、内置 FFmpeg、GPU 环境策略和离线 Wheelhouse 不要求用户重新下载已有作品或模型。
